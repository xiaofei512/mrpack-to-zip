MRPACK Conversion Errors: Missing Files, CORS, and Hashes

Start with the conversion report. It tells you which path failed and whether the converter saw a browser download failure, unsuccessful response, hash mismatch, or unsafe path. Fix the cause shown in the report instead of repeatedly rebuilding the same partial ZIP.

Quick Diagnosis: Read the Reason Code

A partial result means the converter built a ZIP but could not add every target file. Download the report before closing the page. It records the pack, version, launcher/server target, downloaded count, missing path, reason code, and message.

Reason code What it means Best next action
download_failed The browser could not download any listed URL. Check the pack version page and obtain the approved file manually.
invalid_response The file URL returned an unsuccessful HTTP response. Retry later, then verify that the pack still points to an available file.
hash_mismatch The downloaded bytes did not match the manifest hash. Do not use that download; locate the exact file version required by the pack.
unsafe_path The manifest path would leave the ZIP root. Keep it skipped and report the pack to its author or source platform.

Before You Retry the Conversion

  1. Download the report. Keep the pack name, version, target, file counts, missing paths, and reason codes together.
  2. Separate input errors from file errors. If the converter cannot load a project or direct .mrpack URL at all, retry with a local file. If it creates a partial ZIP, changing the input mode will not automatically fix a blocked manifest download.
  3. Keep Launcher ZIP selected unless you need server files. A different target can change which manifest entries are included, but it does not bypass download or integrity failures.

Why CORS Can Cause Missing MRPACK Files

Browser-based tools use fetch() to request files from other origins. Browsers only expose those responses when the remote server permits the request with the required CORS headers. The converter cannot safely override a remote host's policy. See the MDN CORS guide for the browser model.

A CORS failure may appear as download_failed because browser JavaScript receives a generic fetch error. Use the missing path and the pack's version page to locate the correct file manually. Do not assume every download failure is CORS: offline hosts, blocked redirects, and temporary network failures can produce the same report code.

Do Not Bypass a Hash Mismatch

The Modrinth MRPACK specification requires manifest file entries to include SHA-1 and SHA-512 hashes. The converter checks supported hashes before adding a downloaded file to the ZIP.

A hash_mismatch means the downloaded bytes are not the file the manifest describes. Do not disable the check or rename a different mod file to make the warning disappear. Return to the exact pack version, locate the expected dependency, and use the version approved by the pack author.

Invalid Responses and Unsafe Paths

When the report says invalid_response

At least one listed URL returned a non-success response. Retry once to rule out a temporary host failure. If it repeats, check whether the pack version was updated, removed, or points to a file that is no longer public.

When the report says unsafe_path

The converter rejects paths that could escape the ZIP root. Modrinth's specification also warns importers to reject absolute paths, drive paths, and .. traversal. Treat this as a pack safety problem, not a file you should force into the output.

How to Recover a Partial ZIP

  1. Download the partial ZIP and the conversion report.
  2. Open the report and work through each missing path separately.
  3. Find the exact dependency from the pack's version page or author documentation.
  4. Confirm the file version and distribution terms before downloading it.
  5. Place the approved file at the path shown in the report.
  6. Import or test the completed ZIP only after every required path is accounted for.

A partial ZIP is an incomplete result, not a silent success. Keep the report beside the ZIP until you have resolved or intentionally accepted every missing entry.

If Conversion Stops Before a Report Appears

  • Missing modrinth.index.json: the selected archive is not a valid MRPACK file or does not contain the manifest at its root.
  • Invalid manifest JSON: the manifest cannot be parsed; obtain a fresh copy from the pack source.
  • Project not found: verify the Modrinth project URL, slug, or ID.
  • Direct URL rejected: use a direct .mrpack download URL, or switch to Project ID for a normal Modrinth project page.

MRPACK Troubleshooting FAQ

Can this converter bypass CORS?

No. CORS is enforced by the browser and controlled by the remote file host's response headers. If a host does not permit the request, use the missing file report and the pack's official version page to locate an approved manual download.

Is a partial ZIP safe to import?

Treat it as incomplete. The ZIP may open normally while required mods are absent. Read the report, resolve the missing paths, and test the pack before relying on the result.

Should I ignore a hash mismatch?

No. A mismatch means the downloaded bytes differ from the file described by the manifest. Find the exact expected version instead of bypassing the integrity check.

Retry the Converter or Check the ZIP Target

Once you know the failure type, open the MRPACK to ZIP Converter and retry the appropriate input. If the question is whether you need client or server files, read Launcher ZIP vs Server ZIP before rebuilding.
